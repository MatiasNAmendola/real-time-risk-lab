# Adapter: Kiro (AWS)

Kiro is AWS's agentic IDE. It reads steering files from `.kiro/steering/*.md` with YAML activation frontmatter.

## Files used by this adapter

| File | Purpose |
|---|---|
| `.kiro/steering/product.md` | Product context, `inclusion: always`. |
| `.kiro/steering/tech.md` | Technology stack, `inclusion: always`. |
| `.kiro/steering/structure.md` | Layout and architecture, `inclusion: fileMatch` for Java. |
| `.kiro/hooks/` | Kiro hooks for file, agent, and spec events. |
| `.kiro/specs/` | IDE-generated specs; do not create manually. |

## Inclusion frontmatter

```yaml
---
inclusion: always
# or:
inclusion: fileMatch
filePatterns:
  - "src/**/*.java"
  - "src/**/*.ts"
# or:
inclusion: manual
---
```

## Foundation steering files

- `product.md` — purpose, users, features, objectives.
- `tech.md` — frameworks, libraries, tools, constraints.
- `structure.md` — file layout, naming, import patterns.

## Kiro hooks

Configured in `.kiro/hooks/*.kiro.hook`.
Available events:
- File events: `fileCreated`, `fileSaved`, `fileDeleted`.
- Agent lifecycle: `agentSpawn`, `userPromptSubmit`, `preToolUse`, `postToolUse`, `agentStop`.
- Spec task events: `preTaskExecution`, `postTaskExecution`.

Hooks receive JSON events through STDIN.

## How Kiro consumes primitives

1. Kiro reads `.kiro/steering/` when the workspace opens.
2. `inclusion: always` steering applies to every context.
3. `inclusion: fileMatch` steering applies when matching files are in context.
4. `.ai/` primitives are referenced from steering files.
5. `.kiro/specs/` is Kiro's native planning mechanism and is generated by the IDE.

## Known limitations

- Global steering in `~/.kiro/steering/` is not versioned with this project.
- Specs in `.kiro/specs/` are generated by the IDE; do not create them manually.
- Hooks require the IDE to be running; they are not git hooks.
